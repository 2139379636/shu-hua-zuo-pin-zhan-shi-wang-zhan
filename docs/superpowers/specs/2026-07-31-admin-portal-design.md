# admin.html 隐藏管理入口 — 设计文档

**日期**：2026-07-31
**作者**：Claude
**状态**：草案（待用户审阅）

---

## 1. 背景与动机

作品集网站长线运行，需支持客户（画家本人）日常更新作品信息（标题/价格/年份/题画诗等），但：

- ❌ 不希望双端分离（客户页 + 管理后台）—— 维护成本高
- ❌ 不希望直接改源代码（客户不会写代码）
- ❌ 需求是"轻量化"

**方案**：在同站点增设一个**隐藏的管理入口**（admin.html），通过口令进入，可编辑作品数据，导出 JSON 后由开发者合入源码。

---

## 2. 决策记录（已与用户确认）

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 入口方式 | `admin.html?key=xxx` 隐藏 URL | 不暴露在导航栏/页脚/搜索 |
| 口令校验 | 方案 1：前端 sha256 hash 比对 | 极轻，零后端 |
| 上下架 | **真删除**（localStorage 立即清除） | 用户明确"按字面真删除" |
| 图片来源 | 仅文字 + 图片 URL 粘贴 | 客户上传到微信/网盘后粘贴 URL |
| 预览模式 | **无**（仅导出 JSON） | 用户选择"仅导出 JSON" |
| 新增能力 | 可增可删 | 用户选择"可增可删" |
| 数据存储 | `localStorage`（仅当前浏览器） | 轻量方案不引入数据库 |

### 3.2 OUT OF SCOPE

- 不修改 `lib/artworks-data.js`（它是默认数据源，admin 操作不写回源码）
- 不实现真实图片上传（客户自己传到微信/网盘后粘贴 URL）
- 不做撤销/软删除（用户明确"按字面真删除"）
- 不做实时预览（用户选择"仅导出 JSON"）
- 不做修改历史/审计日志
- 不做用户管理 / 多账号

## 4. 架构

### 4.1 模块图

```
┌────────────────────────────────────────────────────────┐
│ admin.html (静态 HTML)                                  │
│   ├─ 入口校验：URL ?key=xxx → sha256 比对               │
│   └─ UI 容器：列表/编辑/添加/导出                        │
│         ↓                                              │
│   lib/admin.js (主程序)                                  │
│     ├─ bootAuth()：URL 校验                              │
│     ├─ renderList()：渲染 19 张作品列表                  │
│     ├─ openEditor(id?)：打开编辑/新增表单                │
│     ├─ saveArtwork(data)：写入 localStorage             │
│     ├─ deleteArtwork(id)：从 localStorage 真删除         │
│     ├─ exportJSON()：生成 + 下载 JSON 文件              │
│     └─ importJSON(file)：导入 JSON 文件                 │
│         ↓                                              │
│   localStorage (浏览器本地)                              │
│     └─ hgm_admin_artworks / poems / brand / meta        │
└────────────────────────────────────────────────────────┘
```

### 4.2 入口安全

```js
// lib/admin.js 顶部
const ADMIN_KEY_HASH = 'a1b2c3d4e5...'; // sha256(secret) 预编译硬编码
const SECRET_PLACEHOLDER = '黄桂明2026'; // 实际部署时换成用户口令的 hash

// 校验流程
function bootAuth(){
  const params = new URLSearchParams(location.search);
  const key = params.get('key') || '';
  if (!key) return showError('缺少口令');
  const hash = sha256(key);
  if (hash !== ADMIN_KEY_HASH) {
    showError('口令错误');
    // 不写 console.log，避免提示攻击路径
  }
  showAdmin();
}
```

**安全边界声明**：
- 客户端纯静态方案，**真正的安全底线是"客户只看不想改"**
- 任何懂 JS 的用户可读源码后修改 hash 比对
- 缓解措施：客户端口令 hash + URL 隐藏 + 浏览器隔离（恶意改 localStorage 只影响该浏览器）

## 6. 实施步骤

1. **数据契约**：admin.js 顶部定义默认数据（从 lib/artworks-data.js 复制）
2. **入口校验**：bootAuth() + sha256 hash 校验
3. **列表渲染**：renderList() 引用 escapeHtml + 模板字符串
4. **编辑/添加**：openEditor(id?) + 13 字段完整表单
5. **保存/删除**：saveArtwork() / deleteArtwork()
6. **导出 JSON**：exportJSON() 容错处理（含导出时间戳）
7. **导入 JSON**：importJSON() 校验 + 覆盖
8. **资源版本号**：admin.html 引入 lib/admin.js? + lib/admin-preview.js?
9. **测试**：手动 + 自动化

## 8. 风险与边界

| 风险 | 应对 |
|------|------|
| 客户误操作真删除 | 按用户决策保留硬删除；可后续加 soft-delete 兜底 |
| 客户跨设备编辑 | 当前方案仅 localStorage；跨设备需手动导出/导入 |
| 客户修改 PHP/JS 越权 | 前端校验永远可被绕过；安全边界由"客户只看不想改"承担 |
| localStorage 满（约 5MB） | 19 张作品 JSON < 50KB，远低于上限 |
| 浏览器禁 localStorage | 降级到 `window.__hgm_admin_fallback` 内存对象 + 提示 |
| 字段格式破坏 | 导入时 schema 校验，错误字段高亮 |
